# Using the runner Docker image

## Pull the published image

```shell
docker pull ghcr.io/<owner>/ansible-runner:latest
```

Replace `<owner>` with the GitHub user or organisation that owns the
repository (e.g. `eudicy` for this fork).

## Show usage help and available playbooks

Running the image without `PLAYBOOK` prints usage help and the list of
available playbooks:

```shell
docker run --rm ghcr.io/<owner>/ansible-runner:latest
```

## Runtime mounts

Secrets are never baked into the image; they are host-mounted at
runtime.

| Host path | Container path | Mode | Purpose |
| --- | --- | --- | --- |
| `<repo>/inventories` | `/ansible/inventories` | rw | Vault secrets (`group_vars/all/vault.yml`) and local state written by the plays: `*_autogenerated.yml` inventories and `*_known_hosts` files. Without this mount, created VMs are unreachable by later runs. |
| `~/.ssh/id_ansible_ed25519` | `/root/.ssh/id_ansible_ed25519` | ro | SSH private key for connecting to managed hosts. Pass `--private-key /root/.ssh/id_ansible_ed25519` to the play. |
| backup directory (optional) | e.g. `/backup` | rw | Only for `backup.yml` / `restore.yml` with `BACKUP_DIR` overridden. |

The `inventories` mount is deliberately read-write: `create-vm.yml`
writes the autogenerated inventory and the project-scoped `known_hosts`
file there (see
[ADR-003](../../decisions/003-ssh-host-key-verification-policy.md)),
and `destroy-vm.yml` removes them again. The mount keeps this state on
the host across container runs.

## Environment variables

| Variable | Required | Default | Purpose |
| --- | --- | --- | --- |
| `PLAYBOOK` | yes | — | Repo-relative playbook path, e.g. `playbooks/create-vm.yml`. |
| `ANSIBLE_VAULT_PASSWORD` | for vaulted vars | — | Vault password; consumed by `scripts/echo-vault-password-environment-variable.sh` via `ansible.cfg`. |
| `HCLOUD_TOKEN` | for `provider=hcloud` | — | Hetzner Cloud API token. |
| `AWS_ACCESS_KEY_ID` | for `provider=aws` | — | AWS access key. |
| `AWS_SECRET_ACCESS_KEY` | for `provider=aws` | — | AWS secret key. |
| `AWS_DEFAULT_REGION` | no | `eu-north-1` | AWS region for provisioning and inventory queries. |
| `BACKUP_DIR` | no | `configuration/home/my_desktop_user/backup` | Backup location for `backup.yml` / `restore.yml`. |

## Create a Hetzner Cloud VM

```shell
docker run --rm \
  -v "$(pwd)/inventories:/ansible/inventories" \
  -v ~/.ssh/id_ansible_ed25519:/root/.ssh/id_ansible_ed25519:ro \
  -e ANSIBLE_VAULT_PASSWORD \
  -e HCLOUD_TOKEN \
  -e PLAYBOOK=playbooks/create-vm.yml \
  ghcr.io/<owner>/ansible-runner:latest \
  --extra-vars provider=hcloud \
  --private-key /root/.ssh/id_ansible_ed25519
```

## Configure the profile on the created VM

```shell
docker run --rm \
  -v "$(pwd)/inventories:/ansible/inventories" \
  -v ~/.ssh/id_ansible_ed25519:/root/.ssh/id_ansible_ed25519:ro \
  -e ANSIBLE_VAULT_PASSWORD \
  -e PLAYBOOK=playbooks/configure-profile.yml \
  ghcr.io/<owner>/ansible-runner:latest \
  --private-key /root/.ssh/id_ansible_ed25519
```

## Create an AWS VM

```shell
docker run --rm \
  -v "$(pwd)/inventories:/ansible/inventories" \
  -v ~/.ssh/id_ansible_ed25519:/root/.ssh/id_ansible_ed25519:ro \
  -e ANSIBLE_VAULT_PASSWORD \
  -e AWS_ACCESS_KEY_ID \
  -e AWS_SECRET_ACCESS_KEY \
  -e AWS_DEFAULT_REGION \
  -e PLAYBOOK=playbooks/create-vm.yml \
  ghcr.io/<owner>/ansible-runner:latest \
  --extra-vars provider=aws \
  --private-key /root/.ssh/id_ansible_ed25519
```

## Destroy a VM

```shell
docker run --rm \
  -v "$(pwd)/inventories:/ansible/inventories" \
  -v ~/.ssh/id_ansible_ed25519:/root/.ssh/id_ansible_ed25519:ro \
  -e ANSIBLE_VAULT_PASSWORD \
  -e HCLOUD_TOKEN \
  -e PLAYBOOK=playbooks/destroy-vm.yml \
  ghcr.io/<owner>/ansible-runner:latest \
  --extra-vars provider=hcloud \
  --extra-vars hostname=<hostname> \
  --private-key /root/.ssh/id_ansible_ed25519
```

## Detached mode

Long-running plays (e.g. `configure-profile.yml` takes 10–15 minutes)
can run detached; follow the log output separately:

```shell
docker run -d --name configure-profile \
  -v "$(pwd)/inventories:/ansible/inventories" \
  -v ~/.ssh/id_ansible_ed25519:/root/.ssh/id_ansible_ed25519:ro \
  -e ANSIBLE_VAULT_PASSWORD \
  -e PLAYBOOK=playbooks/configure-profile.yml \
  ghcr.io/<owner>/ansible-runner:latest \
  --private-key /root/.ssh/id_ansible_ed25519

docker logs -f configure-profile
docker rm configure-profile
```

## Unsupported in the container

The local VM providers `tart` (needs the Tart CLI on macOS) and
`docker` (needs the host Docker daemon) cannot run inside this
container. Use the cloud providers `hcloud` and `aws`, or run those
providers from a normal host checkout.

## Image update notice

The entrypoint compares the baked image version against the latest
GitHub release of this repository (3-second timeout, silent on any
failure) and prints a `docker pull` hint when a newer release exists.
Images built locally carry the version `dev` and skip the check.
